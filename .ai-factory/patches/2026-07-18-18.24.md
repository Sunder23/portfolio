# TaxonomyEditor bypassed the batch-save draft store — instant push, no Save-all button

**Date:** 2026-07-18 18:24
**Files:** app/src/admin/editors/TaxonomyEditor/index.tsx, app/src/admin/hooks/useEditorData.ts, app/src/admin/editors/TaxonomyEditor/TaxonomyEditor.test.tsx
**Severity:** medium

## Problem

On the Tech Stack admin page, adding a term pushed a commit + triggered a deploy immediately, and the floating "Сохранить всё" button never appeared — even though every other editor (Profile, Skills, Project) batches edits and only commits on click. Reported with two screenshots: the empty bottom-right corner (no button) and the GitHub Actions log showing an immediate `admin: update taxonomies.json (add "Test" to stack)` deploy.

## Root Cause

This was a deliberate, documented scope decision from `.ai-factory/plans/feature-admin-batch-save.md`: `TaxonomyEditor` was explicitly excluded from the batch-save draft store and kept its pre-existing immediate-commit-per-action model (`useAdminSave` called directly from `persist()`). Since nothing was ever staged in `AdminDraftContext` for taxonomy edits, `dirtyPaths` stayed empty and `SaveAllButton` correctly rendered nothing — the button wasn't broken, it had nothing to show. The user's actual desired behavior (confirmed via follow-up question) was for taxonomies to participate in the same batching flow as everything else, reversing that original scope call.

## Solution

Removed `useAdminSave`/`useAdminOperation` from `TaxonomyEditor` entirely. `persist()` now just calls the normal `setTaxonomies()` setter from `useEditorData`, which already stages the change in `AdminDraftContext` — `useEditorData` auto-registers a generic flush (`admin: update taxonomies.json`) for this path, so no per-editor save wiring was needed. This made `markClean` (previously added to `useEditorData`'s return tuple solely to re-baseline TaxonomyEditor's entry after its own immediate save) dead code — removed it, reverting `useEditorData` to a plain 3-element tuple.

One TS build-only gotcha surfaced (`tsc -b`, not caught by `tsc --noEmit -p .`): `{ ...taxonomies, [taxonomyKey]: next }` with `taxonomyKey: keyof Taxonomies` widens every field to optional because TS can't prove which property the computed key overrides — fixed with an explicit `const updated: Taxonomies = {...} as Taxonomies` and a comment explaining why the cast is safe (all three `Taxonomies` fields are homogeneous `string[]`).

Also discovered while verifying: every test run this session via `npx vitest run` reported 6 failures (`localStorage.setItem is not a function`) that I had assumed were a pre-existing, unrelated environment bug. They were not — `npm test` sets `NODE_OPTIONS=--no-experimental-webstorage` (see `package.json`), which `npx vitest run` skips, leaving Node's broken experimental `localStorage` shadowing jsdom's. Running via `npm test` gives 31/31 green. No code bug existed; the invocation was wrong.

## Prevention

- When a plan explicitly scopes an editor out of a shared mechanism (draft store, batching, etc.), treat that as a hypothesis to validate with the user after shipping, not a permanent decision — flag it for a quick manual check rather than assuming it's settled.
- Always run this project's tests via `npm test`, never `npx vitest run` directly — the latter silently drops `NODE_OPTIONS=--no-experimental-webstorage` and produces misleading `localStorage` failures that look like a broken environment.
- When adding a hook return value (like `markClean`) to support exactly one caller's special case, remove it again the moment that caller's need goes away — don't leave speculative API surface around "in case something else needs it later."
