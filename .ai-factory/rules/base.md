# Базовые правила проекта

> Проект пока пустой (кода нет) — правила ниже зафиксированы на основе решений из `PLAN.md` / `.ai-factory/DESCRIPTION.md`. По мере появления кода этот файл стоит актуализировать через `/aif-rules`.

## Соглашения об именовании

- Файлы компонентов: PascalCase (`ProjectCard.tsx`, `TokenGate.tsx`).
- Хуки: camelCase с префиксом `use` (`useLocalized.ts`).
- Обычные модули/утилиты: camelCase (`github.ts`, `data.ts`).
- Типы и интерфейсы: PascalCase, локализуемые поля — через generic-хелпер `Localized<T>`.
- JSON-данные (`data/*.json`): snake_case для ключей, если это не поле, уже described схемой в PLAN.md (например `shortDescription` — camelCase, как зафиксировано в схеме).

## Структура модулей

- `src/pages/` — только страницы-роуты (Home, Projects, ProjectDetail, About, Admin).
- `src/components/` — переиспользуемые UI-компоненты публичной части (включая скопированные shadcn/ui в `src/components/ui/`).
- `src/admin/` — весь код админки изолирован здесь (`AdminLayout`, `TokenGate`, `editors/`, `github.ts`, `registry.ts`).
- `src/lib/` — загрузка/типизация данных, не завязанная на UI (`data.ts`).
- `src/locales/` — словари react-i18next по языкам (`uk.json`, `ru.json`, `en.json`).
- `data/` — единственный источник истины для контента; изменяется только через админку (или вручную для локальной разработки).
- Новая сущность контента добавляется как тройка: JSON-файл в `data/` + тип в `types.ts` + редактор в `admin/editors/` + запись в `admin/registry.ts`. Общий код (`github.ts`, `lib/data.ts`) не меняется.

## Обработка ошибок

- Запись через GitHub Contents API: конфликт `sha` (409) обрабатывается одним повтором `GET`+`PUT`, при повторной неудаче — явная ошибка пользователю, а не тихий сбой.
- Истёкший/невалидный PAT (401) — сброс на `TokenGate`, а не необработанное исключение.
- Ошибки записи/загрузки данных показываются пользователю в админке (toast/notification), не проглатываются молча.

## Логирование

- Отдельного серверного логирования нет (проект полностью статичный, без сервера).
- В админке — только пользовательские уведомления об успехе/ошибке операций (например, «Сохранено. Деплой займёт ~1–2 минуты»), без вывода технических деталей PAT/токенов в UI или консоль.

## Тесты

- Стек тестирования не зафиксирован в PLAN.md — определяется при первой реализации (Vitest + React Testing Library — стандартный выбор для связки Vite + React, рекомендуется при старте `/aif-plan`).
