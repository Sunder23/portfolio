# Дизайн-система публичной части: пиксельный терминал

Публичная часть сайта (Home/Projects/ProjectDetail/About/Contact) оформлена в стиле retro-терминала — пиксельные акценты, ASCII-команды вместо обычных заголовков, две терминальные палитры (светлая/тёмная). Админка (`/#/admin`) в этот стиль не входит и не затрагивается.

## Токен-скоуп `.pixel-terminal`

Стиль подключён через один CSS-класс `.pixel-terminal` на корневом `<div>` `PublicLayout` (`app/src/components/PublicLayout/index.tsx`), а не через форк shadcn-компонентов из `components/ui/*`. Это то же архитектурное решение, что уже применяется в проекте для расширения через реестр/токены вместо ветвления кода (см. `.ai-factory/ARCHITECTURE.md`):

- `.pixel-terminal { ... }` в `app/src/index.css` переопределяет `--background/--foreground/--primary/--accent/--muted/--border/--radius/--font-heading/--font-sans` — светлый вариант «бумажный терминал».
- `.dark .pixel-terminal { ... }` — тот же набор переменных для тёмного варианта «фосфор», по аналогии с тем, как `.dark` уже переопределяет `:root` для остального сайта. Тумблер темы в `Nav` (next-themes) работает без изменений — он просто переключает класс `.dark` на `<html>`, а какой из двух терминальных наборов токенов применится, решает CSS.
- `--radius: 0px` внутри скоупа — квадратные углы у Button/Card/Badge/Input автоматически, без правки самих shadcn-компонентов (они читают `--radius-lg` и т.д., которые выведены из `--radius`).

Поскольку класс `.pixel-terminal` не вешается ни на `<html>`, ни на `<body>`, а только на корень `PublicLayout`, админка (`AdminLayout` и всё под ним) эти токены не видит и остаётся на обычной shadcn-палитре и Geist.

### Почему не форк shadcn-компонентов

`components/ui/*` — плоские файлы, которые ожидает `npx shadcn add`/`diff` (см. `.ai-factory/ARCHITECTURE.md`, раздел «Конвенция: компонент = папка»). Правка их классов напрямую сломала бы штатное обновление через CLI и задела бы админку, которая использует те же компоненты. Токен-скоуп решает это без единого `if`: любой компонент, который уже использует `bg-primary`/`text-foreground`/`rounded-lg` и т.п., автоматически подхватывает терминальный вид внутри `PublicLayout` и обычный — внутри `AdminLayout`.

## Палитра

Первый ручной проход показал, что тёмный вариант был перенасыщен неоновым зелёным — `--foreground` и `--primary` использовали один и тот же максимально яркий зелёный, из-за чего весь текст и все бейджи/кнопки сливались в «стену неона» без иерархии. Исправлено:

| Токен | Было | Стало | Почему |
|---|---|---|---|
| `--foreground` (dark) | `#39ff6a` (неон) | `#a9d9b4` (мягкий шалфейный) | Обычный текст не должен быть на максимуме яркости — иначе нет иерархии с акцентами |
| `--primary` (dark) | `#39ff6a` (неон) | `#1c4a26` (тёмно-зелёный) + `--primary-foreground: #eafff1` | Заливка кнопки перестала быть слепящим неоновым прямоугольником |
| `--border` (dark) | `#163a1f` (почти не виден) | `#234a2c` | Рамки карточек/бейджей были почти невидимы на `#0a0d0a` |

`--accent` (янтарный `#ffb000`) не менялся — он единственный несёт полную яркость и используется точечно (заголовок-должность, активный пункт навигации, hover-подсказки), поэтому не создаёт эффекта «всё зелёное».

## Шрифт

`@fontsource/vt323` — самохостится тем же способом, что и уже использованный `@fontsource-variable/geist` (импорт в `app/src/index.css`, без внешних CDN). Внутри `.pixel-terminal` он подключён как `--font-heading` и применяется через utility-класс `font-heading` — на заголовках, `CommandLabel`, кнопках и лейблах. Основной текст (био, markdown-описания) остаётся на системном monospace-стеке (`--font-sans` внутри скоупа), чтобы длинные абзацы не читались тяжело — VT323 используется только как display-шрифт, не как шрифт для длинного текста.

## Общие компоненты

| Компонент | Путь | Назначение |
|---|---|---|
| `Scanline` | `app/src/shared/Scanline` | Декоративный CRT-оверлей (scanlines), один экземпляр монтируется в `PublicLayout`. Отключает анимацию при `prefers-reduced-motion: reduce`. |
| `CommandLabel` | `app/src/components/CommandLabel` | Заменяет обычные `<h1>/<h2>` на секциях: рендерит `$ <children>` в `font-heading`. Проп `label` задаёт `aria-label` — screen reader слышит человеко-читаемый текст (например «About me»), а не стилизованную команду (`cat about.md`). Используется на всех публичных страницах. |
| `TerminalCursor` | `app/src/components/TerminalCursor` | Мигающий `_` рядом с именем в hero (Home). `aria-hidden`, анимация отключается при reduced motion. |
| `Footer` | `app/src/shared/Footer` | Футер публичной части: локация, email, соцсети из `profile.json`. Монтируется только в `PublicLayout`, в админке не используется. |

## Как расширять

Новая публичная страница/секция получает терминальный вид «бесплатно», если:

- использует существующие компоненты (`Button`, `Card`, `Badge` и т.п.) — цвета/радиус подхватятся из токен-скоупа автоматически;
- заголовки секций оформляются через `<CommandLabel label="...">...</CommandLabel>` вместо голого `<h1>/<h2>`, чтобы сохранить и стиль, и доступное имя для screen reader;
- декоративные/стилизованные ASCII-вставки (`$ `, `> `, `[ ]`) помечаются `aria-hidden`, а видимый доступный текст остаётся обычным переводом через `t(...)`.

Хардкодить цвета или `rounded-*` вручную не нужно — если что-то не подхватывает стиль, вероятная причина в том, что элемент рендерится вне `PublicLayout`, а не в отсутствии класса.
